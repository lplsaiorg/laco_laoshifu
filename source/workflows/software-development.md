# 程序开发工作流

本文件是面向光伏工艺、设备数据、质量与 OEE 程序的开发建议，不代表存在某种既定技术栈或数据库。先阅读实际仓库约定和相关代码，再按任务读取[设备知识](../knowledge/equipment.md)、[数据工作流](data-analysis.md)和[缺口清单](../knowledge/gaps-and-conflicts.md)。

## 把业务问题写成契约

开始实现前，用实际需求确定输入、输出、对象粒度、时间与单位、规则来源和失败行为。字段名称、状态码、表结构、采样协议及接口均从真实文件或代码取得；下表仅是建模检查项，不是现有接口：

| 检查项 | 需要表达的语义 |
|---|---|
| 设备层级 | 整机、炉管、温区/传感器的关系与归属变化；不能假定整机只有一管 |
| 生产追溯 | 批次、舟、单片、工序及配方版本关联；不能仅以设备号连接所有记录 |
| 测量 | 原值、原单位、规范值、质量码、时间、设定/实测标志及来源 |
| 状态/事件 | 原始码、映射规则版本、事件时间、接收时间、有效区间、唯一事件身份 |
| 产量/质量 | 投入、完成、合格、报废、返工、重测分别定义；累计与增量区分 |
| 规则 | 技术路线、工序、规格、配方版本、适用设备、有效期和规则出处 |

原文关于多温区、舟式批量和管式 PECVD 的结构见[15 一/1.2、四/4.2](../references/kd/15_tube_furnace_equipment.md)。具体数据层级仍以现场定义为准。

## 将业务知识用于实现决策

- 单位转换集中处理，拒绝或显式保留未知单位；压力基准、流量标准状态未知时不能仅换数字便认为可比较。
- 缺失、无效测点和通信故障使用明确状态，不能默认成 0；无时间信息的记录不得静默赋当前时间。
- 原始状态码与业务分类分开保存；未知码可见且可追溯。报警与停机相关但不等价，不能以“有报警”直接改写设备停机。
- 事件处理考虑重复、乱序、迟到、断链、计数器复位及跨班；是否允许重算和如何版本化由产品要求确定。
- 批量设备的实际装载、配方周期、并行炉管和完成事件分别建模；不要使用行业“典型周期”作为现场理想节拍。
- 同一 PECVD 名称可能对应 SiNₓ 减反射、TOPCon 三合一或 HJT a-Si:H，不用单个设备类型判断所有工艺限值。
- 对阈值、理想周期、维护周期和状态映射使用项目已有配置方式，并记录适用范围。原文参数只是知识参考，不能直接硬编码为报警、安全联锁或配方设定。

既有系统行为明确时优先保持兼容；改动口径需要给出前后差异和适用版本。缺口不妨碍实现解析、映射、可视化或配置接口，但缺失规则不能用任意默认值伪装为正式计算。

## 验证实际业务边界

依据本次改动选择有意义的测试，不为低影响文案修改新增冗余测试。涉及计算、时间和单位时，使用可手算的最小样本验证：

| 场景 | 可观察的期望 |
|---|---|
| 两炉管同时运行 1 小时 | 保留各管 1 小时；整机自然窗口仍为 1 小时，容量聚合按已定义口径 |
| 跨午夜/跨班事件 | 区间裁剪前后总时长守恒；边界归属与系统约定一致 |
| 报警重叠或乱序到达 | 不重复计停机时间；未知起止与数据缺口可见 |
| 同一事件重复输入 | 在任务要求幂等时结果不翻倍，并保留可追溯记录 |
| 计数器复位/重测 | 不产生虚假负产量或重复合格片，规则未知时报告异常 |
| 压力含 Pa 与 mbar | 经确认同一基准后可换算比较；未知基准仍保留标记 |
| 更换配方版本/装载量 | 规则按正确版本匹配，不把不同适用范围混算 |
| 分母为零或质量未知 | 按约定返回未定义/缺失及原因，不静默返回满分 |

质量特征与工艺值关联测试需核对实体键和时间窗口，防止未来信息泄漏。若实现统计/模型，按批次、设备或时间组织验证集合，避免同批采样随机拆分造成虚高效果；采用何种划分取决于实际预测目标。

## 输出与交付

把改动、业务依据、验证结果和已知限制一并交付。分析/规则输出建议包含计算版本、输入范围、对象粒度、单位、有效覆盖和异常原因；使用当前项目的日志与元数据机制，不另造无需求的平台。

若任务涉及设备写入、生产数据库变更或配方控制，先完成代码、离线样本验证和可审查结果，再按用户已给授权及实际权限执行后续动作。本知识库不扩大任务授权，也不提供现场设备控制参数。
