# 文档编写工作流

本文件规定使用知识库撰写报告、工艺说明、分析结论和开发文档的建议方式。业务背景从[工艺图谱](../knowledge/process-map.md)、[设备知识](../knowledge/equipment.md)和[质量与材料](../knowledge/quality-and-materials.md)按需读取。

## 按读者与用途选择证据

先识别读者和用途：工艺人员需要路线、步骤与条件；设备人员需要对象层级、信号与维护背景；数据人员需要口径与数据来源；管理报告需要结论、量化依据、影响范围和待决事项。沿用用户已有模板及术语，不强制重写结构。

建立最小证据链：工作问题 → 相关知识条目 → 原始章节 → 本次数据或代码证据。原始资料在[参考目录](../references/kd/00_index.md)。引用应能定位文件和章节；原文件只列出的外部链接仍是二手引用，未实际查阅不能写成“已验证”。

## 区分内容性质

| 内容 | 写法 |
|---|---|
| 原资料中的背景事实 | 标明资料文件和章节，不把行业背景写成该厂事实 |
| 典型参数/经验范围 | 标明工艺路线、步骤、单位及“参考值”，不称为现场合格线 |
| 本次数据观察 | 标明数据时间、粒度、样本数、清洗规则和有效覆盖率 |
| 推导或假设 | 给出推导依据、假设和可验证方式，避免肯定因果 |
| 建议 | 说明解决的问题、预期作用及需补充的验证，不冒充已批准要求 |
| 未确认/有冲突 | 明确列为待确认，关联[缺口清单](../knowledge/gaps-and-conflicts.md) |

用户提供的已批准现场配方、SOP、数据字典优先用于解释现场任务；记录版本和适用范围。它与参考资料不一致时，应写明差异，不能悄悄覆盖原始快照。

## 光伏文档中的易错点

- 写明对象是硅片、电池还是组件；电池效率、组件效率和发电量不能换作同一指标。
- TOPCon、PERC、HJT 的结构和热预算有差异；PECVD 设备名称相同也不代表薄膜、温度和配方可通用。
- 正面/背面、P/N 衬底与 P+/N+ 掺杂层分开描述；原文缩略词首次出现给出中文含义。
- 设备、炉管、舟、批次、片的统计范围分别说明；“批次质量差”不能写成“整机故障”。
- 将 ℃、Pa/mbar/Torr、sccm/SLM、nm、Ω/sq、mV、fA/cm² 等单位写全。描述均匀性时写明片内、片间或批间及所用公式。
- 效率由 25.0% 到 25.2% 是提高 0.2 个百分点；不要含糊地写“提升 0.2%”。
- 引用 STC 时保留辐照度、光谱和电池温度的完整条件，见[13 第1节](../references/kd/13_cell_testing_characterization.md)。
- 区分量产均值、研发结果、认证纪录、预测与目标；出处只标年份的成本/份额数据也不是当前报价或现状。

原资料[10 技术对比与市场现状](../references/kd/10_technology_comparison.md)包含 2025 年数据和预测；[07 TOPCon](../references/kd/07_topcon_cells.md)含 2025–2026 年纪录。可作为带时间的历史背景；当用户需要“当前/最新”结论时应另行查证并记录新来源与查询日期。

## 根据任务形成交付

- 分析报告：先写发现及影响，再给数据依据、口径、解释与建议；没有证据时保留假设，不能用行业参考值补造生产结果。
- 工艺/设备说明：按具体路线和工序说明作用、输入输出、关键观察量及约束。若用户要求可执行 SOP，必须以已批准的现场版本为基础；本资料中的温度、气体和时间仅能形成说明或待评审草稿。
- 需求/设计文档：写清业务对象、数据契约、计算边界、未知项及验收实例，具体方法见[程序工作流](software-development.md)。
- 培训资料：优先解释结构、工序作用和术语，再引用参考范围；把不同路线并列比较时写出适用边界。

没有模板时可采用“目的与范围 → 证据与口径 → 内容/结果 → 限制与待确认 → 建议”的顺序，按任务规模裁剪。保留用户要求的格式与详细程度。

交付前核查每个数字是否有单位、对象、时间和出处；每个判断是否有支持证据；每项建议是否与实测结论区分。对 Word/PDF/幻灯片等成品再执行相应格式的渲染或视觉检查，本工作流只补充业务语义。
