# 名称与缩写消歧工作流

同一英文缩写可以对应多个中文概念。先查候选并结合当前上下文判断；仍不能确定时，必须向用户确认。适用于数据字段、日志、技术文档和程序中的名称解释，不能把查询结果直接当作现场定义。

## 查询候选

```powershell
python source/tools/kb.py abbr "PK" --json
python source/tools/kb.py abbr "OD" --json
```

从 [glossary.json](../glossary.json) 或[名称对照表](../knowledge/name-crosswalk.md)读取候选概念、每个名称的状态、适用范围和出处。保留多个合理候选；没有命中不等于可以自行造义。

`abbr` 只列候选并标记歧义，不按关键词自动选义，也没有 `--context` 参数。JSON 中的 `disambiguation` 是审阅提示：

- `status` 为 `not_applicable|single_candidate|ambiguous|not_found|possible_matches`；单一候选也不证明适用于当前资料，近似命中也不是确认。
- `requires_context_review`、`next_action` 提示 Agent 下一步；`candidates` 提供 `term`、`scopes`、`sources`。
- 有歧义或无命中时的 `confirmation_prompt` 只是建议提问。Agent 先复核已有上下文，仍不能判断时才向用户提出。

## 复核当前上下文

按实际可得证据核对，不要求无关信息齐全：

| 线索 | 需要核对的内容 |
|---|---|
| 原句与任务 | 原句、前后段落、问题目标；是工序名、测量指标还是数据文件类别 |
| 工序与设备 | 上下游工序、设备用途、技术路线、具体配方步骤；相关工序不等于同义词 |
| 字段与测量 | 邻列、单位、多行表头、数据字典及字段说明；列位置相同不证明含义相同 |
| 来源与范围 | 文件路径、厂区/数据集、表名、字段定位、版本、日期和定义生效范围 |
| 已有确认 | 用户已经确认且适用于当前任务的定义；不要为同一适用范围重复询问 |

不得靠第一个命中、缩写大小写、出现频率或拼音首字母选答案。一个名称有多义时，不用全局替换消除差异；新数据源不能盲套旧数据源的定义。

## 判断与说明依据

上下文足以支持一个解释时，说明采用的概念、证据位置和适用范围。若是由上下文推断，明确写成“依据……，本次按……理解（上下文推断）”，不能标成用户确认或全厂标准。

| 现有实例 | 应如何判断 |
|---|---|
| `PK` | 当前用户已确认 PK 指磷扩散，在该约定适用的任务内直接采用；800G 旧文档的 pk=退火保留为历史标签。遇到新来源，核对其版本、工序及字典，不能自动沿用任一解释 |
| `OD` | Longji 资料用于方阻检测，另有 LP 后膜厚检测语境。核对来源说明、邻列和单位后区分；仅看到 OD 或检测文件夹名，不能判定是哪一种 |

这些例子的候选与证据见[名称对照表](../knowledge/name-crosswalk.md)，不要把方阻数据、膜厚数据合并成一个测量概念。

## 仍不能判断时必须确认

若仍有多个合理候选、缺少关键证据，或当前资料与适用定义冲突，必须向用户确认。给出原句或字段定位，以及最相关的 2–3 个候选；无可靠候选时直接请求定义，不为凑选项猜答案。

建议问法：“`文件/表名:行号或字段` 中的 `OD`，这里指方阻检测数据还是膜厚检测数据？该定义适用于哪个数据源或版本？”仅问当前证据无法解决的部分。

收到用户答复前，暂停依赖该语义的运算、字段改名、同义替换及结论发布；结构检查、缺失率统计、候选证据整理等可独立工作继续进行。不能以暂定标签发布确定含义的结果。

答复后保留确认内容及适用范围，并仅在该范围内使用；范围不清且影响任务时继续澄清。上下文推断或一次任务确认不自动写入全库；用户要求维护知识库时，再按[维护 skill](../../skills/kd-knowledge-maintenance/SKILL.md)记录来源、版本、范围和确认状态。
