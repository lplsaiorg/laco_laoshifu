<a id="install"></a>

## 1. 安装并启用

### 准备条件

| 你要做什么 | 所需条件 |
|---|---|
| 查知识、解释术语、按工作流审阅内容 | 已安装 Lapdex，当前会话可读取本地技能和工作材料 |
| 运行知识检索与检查脚本 | Python 3.10+，Lapdex 可执行相应终端工具 |
| 批量规范化 Word、Excel、PPT | Windows、Python 3.10+、PowerShell，以及对应的 Microsoft Office 桌面应用 |

没有可用 Python 时，可以先让助手直接阅读随包资料；检索脚本和 Office 自动处理需要补齐对应依赖。

### Windows 一键安装

完整解压 ZIP，双击包内 `laco-laoshifu/install.bat`。需要先配置可用的 Lapdex CLI，并确保在新终端中能运行 `lapdex`。脚本会把解压目录作为安装路径交给 Lapdex CLI。请查看终端中的实际结果，再到技能列表确认并启用 `laco-laoshifu`。已有同名技能时，按[升级与备份](#upgrade)处理。

### 手动安装技能包

1. 下载 [laco-laoshifu-lapdex-0.2.3.zip](../dist/laco-laoshifu-lapdex-0.2.3.zip)，保留包内完整的 `laco-laoshifu` 文件夹。
2. 在 Windows 文件资源管理器的地址栏输入 `%USERPROFILE%\.lapdex\skills`。默认目录不存在时可以创建；使用自定义技能目录或其他 profile 时，以当前配置的技能目录为准。
3. 将完整的 `laco-laoshifu` 文件夹解压到该技能目录下。最后应能找到下面两个文件：

```text
%USERPROFILE%\.lapdex\skills\laco-laoshifu\SKILL.md
%USERPROFILE%\.lapdex\skills\laco-laoshifu\references\kd\source\README.md
```

4. 等待技能列表刷新；所核对版本约需 30 秒，必要时重新打开 Lapdex。
5. 点击左侧 **“技能与工具”**，选择顶部 **“技能”** 标签，找到 **`laco-laoshifu`（拉可老师傅）**，打开右侧开关。蓝色且圆点在右侧表示已启用。

![技能启用操作位置，按编号点击左侧入口、技能标签和技能右侧开关](images/lapdex-enable-skill.png)

*截图中的 `lapu-laoshifu` 为旧版技能名；当前版本请查找 `laco-laoshifu`。*

安装后只需启用一个入口，内部工作流会按任务读取。保留整个文件夹，确保 `SKILL.md` 与 `references` 文件夹位于同一目录，避免只复制入口文件或多套一层压缩包名称目录。已有同名安装时，先按[升级与备份](#upgrade)处理。

<a id="first-task"></a>

## 2. 先完成一个不用准备文件的小任务

在 Lapdex 对话中输入：

```text
用拉可老师傅查询硼扩散有哪些简称，说明出处和适用范围。
```

查看回答是否引用了随包资料，并说明名称的使用范围。单纯显示技能名称，只能说明入口被发现；完成这次查询后，再检查是否实际读取了本地依据。

也可以继续问：

```text
用拉可老师傅解释 Longji OD 数据中的 ZoneID。
先核对本地资料，说明它和炉管加热温区有什么关系，列出依据。
```

<a id="files"></a>

## 3. 把自己的工作文件交给它

在对话中给出**本地文件或文件夹的绝对路径**，并说明希望得到什么、保存到哪里。下面的路径是示例，使用前替换成自己电脑上的实际路径。

```text
用拉可老师傅审阅“用户选定的材料（设备说明.docx）”。
统一专业术语和单位，检查关键参数与结论的依据，
保留需要确认的地方，沿用原有风格，给我修订稿和修改摘要。
输出到“用户选定的材料（老师傅输出）”，保留原文件。
```

- 文件留在自己的工作目录中；技能安装目录用于保存知识和工具。
- 涉及配方、产品规格、字段定义时，同时提供适用的批准资料或数据说明，并注明版本和范围。
- 当前会话应能读取输入路径、写入输出目录；需要执行脚本时，应具备相应终端工具能力。
- 批量任务给出输入文件夹和新的输出目录；知识维护任务则明确说明哪些资料需要更新。

助手会从已安装的技能入口读取工作流。安装后的日常使用可直接点名“拉可老师傅”，无需切换到开发仓库或手动指定 `AGENTS.md`。

<a id="tasks"></a>

## 4. 常用任务，直接复制后替换路径

### 查知识、解释内部简称

```text
用拉可老师傅解释“用户选定的材料（字段说明.md）”里的 BK、PE、OD。
结合来源、邻近字段和单位判断；有多个合理含义时列出候选，
不要直接合并或改名，给出出处和待确认项。
```

### 编写或修订技术说明

```text
用拉可老师傅整理“用户选定的材料（技术资料）”中的现有材料，
写一份设备技术说明。沿用已有术语和文档风格，
重要结论给出依据，区分资料事实、推断和待确认项，
输出到“用户选定的材料（说明输出）”。
```

### 检查数据与统计口径

```text
用拉可老师傅检查“用户选定的材料（批次数据.csv）”。
先核对字段、单位、批次与炉管粒度、缺失和重复记录，
列出可以分析的内容及缺少的口径，输出检查结果和依据。
```

未提供状态映射、计划时间、理论节拍和质量计数规则时，先检查数据结构与分布，补齐依据后再计算正式 OEE。

### 批量统一 Office 格式和 Logo

```text
用拉可老师傅处理“用户选定的材料（待规范化）”中的 Word、Excel、PPT。
先检查 Office 和 Python 依赖，列出将处理的文件与所用模板版本。
按选定模板统一样式、加 Logo，保留原文件，
输出到“用户选定的材料（规范化输出）”，生成逐文件检查报告和 PDF 复核材料。
```

当前输入格式为 `.docx/.xlsx/.pptx`。旧格式需先转换；宏、数字签名、加密、受保护及外部数据连接文件需使用专门处理流程。内置模板为草案，正式模板可按版本替换。

### 辅助开发与维护知识

```text
用拉可老师傅，依据“用户选定的材料（字段说明.md）”审查清洗程序，
核对单位、输入输出约定、未知值处理和验证条件。
```

```text
用拉可老师傅，将“用户选定的材料（已确认术语.md）”纳入本地知识库。
先核对冲突，保留来源、版本和适用范围，完成后给出修改摘要与校验结果。
```

知识维护写入当前安装副本，不会自动同步到源码仓库或其他同事的电脑。需要分发时，由维护者审核差异并更新发行包。

<a id="results"></a>

## 5. 看结果时检查什么

| 任务 | 重点检查 |
|---|---|
| 知识查询 | 解释是否符合当前来源；出处能否定位到文件与章节；是否说明适用范围 |
| 技术文档 | 修订稿、修改摘要和待确认项是否齐全；重要参数及结论是否有依据 |
| 数据分析 | 数据对象、单位、统计口径、缺失处理是否明确；推断是否与观察分开 |
| Office 处理 | 输出副本、`standardization-report.json`、PDF 复核材料；逐文件状态和版式检查提示 |
| 知识维护 | 更新范围、冲突处理、来源版本和校验记录 |

格式处理以进入该步骤的文件为内容保真基线；如果此前做过内容修订，还需检查相应修改摘要。保存成功或程序检查通过后，继续查看实际输出的标题、分页、表格、图表及 Logo 周边。

<a id="office"></a>

### Office 当前处理范围

| 文件 | 当前处理 | 保留与复核 |
|---|---|---|
| Word | 模板样式、已有语义标题与正文、页边距、页眉 Logo | 检查主正文保真，复杂分节、宽表和页眉需查看 |
| Excel | 字体、指定表头、行列适配、空白区及打印页眉 Logo | 保留数值、公式、数字格式、单元格位置和工作表结构 |
| PowerPoint | 模板、字体、可识别占位符字号、逐页 Logo | 保留画布、页数及原有对象；自由布局和重叠需逐页复核 |

当前工具不自动将任意 Excel 重排为新布局，也不自动重排任意 PPT 自由布局。详细范围见[格式与保真约定](../skills/laplace-office-standardize/references/format-contract.md)。

<a id="troubleshooting"></a>

## 6. 常见问题

| 遇到的情况 | 处理办法 |
|---|---|
| 找不到 `laco-laoshifu` | 核对当前 profile 和实际技能目录；检查目录层级及 `SKILL.md`；等待刷新或重新打开 Lapdex |
| 已显示技能，但回答很泛 | 在任务中点名“拉可老师傅”，要求先读取随包资料、给出具体出处；核对 `references/kd` 是否完整 |
| 只看到一个技能 | 这是本包的组织方式，六类工作流由同一入口按需读取 |
| 读取不到文件 | 检查绝对路径、文件是否存在，以及当前会话的读取能力；把路径替换为自己的实际路径 |
| 提示找不到 Python | 检查 `python`、`python3` 或 `py -3` 是否指向 Python 3.10+；暂时可直接阅读随包资料 |
| 无法处理 Office | 核对 Windows、PowerShell、对应桌面 Office 和可用 Python；先运行依赖检查，查看具体失败项 |
| 输出需要视觉复核 | 打开文档或 PDF，检查版式；保真检查与视觉复核分别确认 |
| “记住”没有跨对话生效 | 确认技能已启用、助手已回执保存成功，并检查新对话使用的项目范围和本机用户目录 |
| 新旧资料含义冲突 | 提供来源、版本及设备范围，先保留差异；影响结论的解释需确认后再继续 |

<a id="commands"></a>

### 可选：在安装目录做命令行自检

通常可以让 Lapdex 代为运行检查。需要自己排查时，下面命令在 **PowerShell** 中执行，不要求切换到源码目录。自定义技能目录的用户，请将第一行改成实际安装路径。

```powershell
$lapdexSkillRoot = Join-Path ([Environment]::GetFolderPath('UserProfile')) '.lapdex\skills\laco-laoshifu'
$lapdexResourceRoot = Join-Path $lapdexSkillRoot 'references\kd'

# 使用当前电脑可用的 Python 3.10+；也可将 python 替换为 py -3
python (Join-Path $lapdexResourceRoot 'source\tools\kb.py') abbr '硼扩散' --json
python (Join-Path $lapdexResourceRoot 'source\tools\kb.py') verify
python (Join-Path $lapdexResourceRoot 'skills\laplace-office-standardize\scripts\office.py') doctor
```

`verify` 检查本地资料完整性，不代表工艺适用性已经核准；`doctor` 检查依赖、配置和模板，不会启动 Office，也不代表版式已经验收。

<a id="upgrade"></a>

## 7. 升级前备份知识

安装副本可能已积累用户维护的知识。升级前：

1. 暂停涉及知识修改的任务，备份完整的 `laco-laoshifu` 目录。
2. 将备份放到技能扫描目录以外，避免同时发现新旧入口。
3. 对比旧知识与新版内容，保留已确认的本地修改及其来源、版本和范围。
4. 核对备份完整后，将原安装目录移到技能扫描目录之外，腾出安装位置；再将新版完整解压到原安装位置。
5. 由维护者合并需要保留的知识，检查后再恢复使用。

不要用直接覆盖文件夹的方式跳过差异核对。源码安装器也会拒绝覆盖已有目标；安装脚本及打包方式见[发行分支的技术说明](lapdex.md)。

<a id="version"></a>

## 8. 本版能力与验证范围

**v0.2.3 提供一个技能入口和六类工作流：**业务知识与名称消歧、数据分析、技术文档、程序开发、知识维护、Office 规范化。无需分别安装内部六个技能。

<a id="memory"></a>

**v0.2.0 起支持“爱学习”本机私有记忆。** 明确要求记住或确认长期保存后，助手才会把约定写入当前系统用户目录下的 `~/.laco-laoshifu/private-memory/`。记忆按项目或数据源范围复用，跨对话需要启用技能并能访问同一目录。升级技能包时，私有记忆目录独立保留。

- 保存：“用拉可老师傅记住：本项目报告先写结论。”
- 查看：“用拉可老师傅查看本项目记忆。”
- 管理：“把本项目的报告顺序改成先写背景”“忘掉这条报告顺序约定”或“回退到这条约定的上一个版本”。

当前发行适配依据为已静态核对的 Lapdex `2026.6993.738.0`。发行包已完成打包、归档校验、隔离安装和知识库检查；**Lapdex 中的实际发现、启用、任务调用及文件输出尚待实机验证**。新版本 Lapdex 或自定义配置需重新核对。

首页和案例页保留的是已有知识与 Office 工具的实际示例，不能作为 Lapdex 实机调用记录，也尚无统计意义上的准确率或工时收益结论。

## 发行隐私检查

v0.2.3 清除了本机路径、文档作者字段和外部模板链接。发布历史已重写，旧发行标签已撤下。已有克隆应重新克隆，避免将旧记录推回。包内相对路径只用于技能目录中的资源。用户材料、输出目录和私有记忆由运行环境或用户明确指定。
