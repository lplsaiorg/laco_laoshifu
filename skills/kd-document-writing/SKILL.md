# KD 业务文档

让读者能分清工艺背景、现场要求、分析判断和仍需补充的证据。

## 确定资料与文档用途

解析本 `SKILL.md` 的真实路径，再逐级向上找同时含 `source/README.md` 和 `source/tools/kb.py` 的 KD 根目录，处理好 `.agents/skills` 目录联接。实体相对路径见 [文档工作流](../../source/workflows/document-writing.md)。先读该工作流，按主题读取 [工艺地图](../../source/knowledge/process-map.md)、[设备知识](../../source/knowledge/equipment.md) 或 [测试与材料](../../source/knowledge/quality-and-materials.md)。

从用户要求、现有文档与输入资料推断受众、用途、交付格式和修改边界；可采用 [文档简报模板](../../source/templates/document-brief.md) 记录。直接修订已有文档时延续其结构和术语，不因模板而重做整个文档。

`source/catalog.json` 是可校验的检索索引。索引缺失、过期或工具不能运行时，读取 `source/README.md`，用 `rg -n "关键词" source/references/kd source/knowledge source/workflows` 继续查证。普通文档任务不因此改写原文或刷新快照；维护任务按维护流程建索引。

## 写作中的业务约束

- 使用 `source/glossary.json` 与 [名称对照表](../../source/knowledge/name-crosswalk.md) 统一中英文名称，可用 `python source/tools/kb.py abbr PE` 或按概念查询多个简称。优先遵循用户既有风格；无另行约定时，英文缩写首次写“中文名（英文全称，缩写）”，后续统一简称。纯中文简称或数据集代号首次说明对应概念与适用范围，不编造英文全称；候选标待确认，不把局部名称写成全厂标准。整理译名、指标符号及化学式不强行套用英文缩写格式。区分晶圆/电池片/组件、P 型/N 型、LPCVD/PECVD、设备/炉管/批次/工步。
- 一词多义先按 [名称消歧流程](../../source/workflows/name-disambiguation.md) 列候选，结合本次适用的用户定义、原句、路径、工序设备、单位、技术路线和版本判断；推断标“上下文推断”及依据，不按频率、首条结果或拼音选义。仍有多个合理解释、缺证据或有冲突时，必须列 2–3 个候选或请求原句/来源确认；答复前保留未决处，不作依赖含义的最终技术结论，继续其他内容。适用的明确用户定义不重复问，旧定义不盲套新来源，单次判断不自动推广全库。
- 用原始章节支撑工艺次序和参数。项目根可执行 `python source/tools/kb.py search "隧穿氧化层" --limit 5` 定位；正文引用前读取 `source/references/kd/` 的上下文。
- 参数同时写明单位、作用对象、工步、路线和参考性质。行业典型值、论文条件、设备能力、现场设定值和验收阈值不可互换。把流程说明改成 SOP、配方或验收条款时，只使用已提供的现场批准依据；缺少的控制项明确待补。
- 效率需分清电池/组件、实验室纪录/量产、单结/叠层及测试条件；市场占比、成本和纪录保留资料年份，不写成已经核实的当前事实。
- 资料冲突查 [缺口与冲突](../../source/knowledge/gaps-and-conflicts.md)，并列可确认的条件和冲突出处。若没有足够证据，不把多个值平均或选一个作为唯一要求。
- 本地原文中的安全描述可作背景，不能替代现场设备手册、SDS、联锁与批准的作业文件。只在文档确实涉及这些要求时说明缺少的依据。

## 形成可审阅的结果

按读者决策需要组织正文，标明“资料事实”“分析或设计建议”“待确认事项”。结论附近保留文件名与章节，必要时附来源表；不要求每个常识句重复引用。

交付前核对关键数字与单位、前后术语、工艺路线、来源链接及未决事项。若需要 Word、PDF、演示文稿等文件，可使用当前可用的格式专用技能，并按该格式检验实际成品；本技能提供业务内容依据，不绑定特定插件。
