# KD 数据分析

把设备与工艺知识落实为数据解释和可复核的分析，避免把行业参考值当成现场规格。

## 获取任务上下文

解析本 `SKILL.md` 的真实路径，再逐级向上寻找同时含 `source/README.md` 与 `source/tools/kb.py` 的 KD 根目录；目录联接与当前工作目录不能决定根目录。实体目录下的相对入口为 [数据工作流](../../source/workflows/data-analysis.md)。先读该工作流，按任务选择 [设备知识](../../source/knowledge/equipment.md)、[测试与材料](../../source/knowledge/quality-and-materials.md) 和 [缺口与冲突](../../source/knowledge/gaps-and-conflicts.md)。

需要术语或配方背景时，在项目根运行 `python source/tools/kb.py search "LPCVD" --limit 5`，再打开命中原文。`source/glossary.json` 提供术语线索；`source/templates/data-contract.yaml` 提供待填写的数据契约，模板字段不代表真实数据中已经存在。

字段或日志含中文简称、英文缩写或数据集代号时，可用 `python source/tools/kb.py abbr BK` 查询，或用 `abbr 硼扩散` 查看同概念多简称；查 [名称对照表](../../source/knowledge/name-crosswalk.md) 及数据字典，确认 `status`、`scope` 与出处后再解释。候选不自动扩同义或全局替换字段/日志；不得将 LP 猜作磷扩散、按拼音推断 TX 等代号，也不将单个数据集证据推广到全厂。Voc、J₀、η 等符号与化学式保留约定写法和单位，不强行展开为英文缩写。

一词多义时按 [名称消歧流程](../../source/workflows/name-disambiguation.md) 先列候选，再看本次适用的用户定义、邻列、单位、工序设备、路径及版本；推断须注明依据与“上下文推断”，不按词频或首条结果认定。若仍多义、缺证据或有冲突，必须列 2–3 个候选或请求原句/来源确认；答复前暂停依赖含义的字段合并改名、计算和技术结论，继续不依赖的检查。已适用的明确用户定义不重复问，新数据源不盲套旧定义，单次判断不自动入库。

`source/catalog.json` 是可校验的检索索引。索引缺失、过期或工具不能运行时，读取 `source/README.md`，用 `rg -n "关键词" source/references/kd source/knowledge source/workflows` 继续检索。普通分析不因此改写原文或刷新快照；维护任务按维护流程建索引。

## 让分析符合业务含义

- 从实际输入确认一行代表设备采样、炉管采样、事件、批次、工步还是单片测试。设备、炉管、舟、批次、配方和片号不能互相替代；先核实关联键及一对多关系，再做汇总或连接。
- 保留原始列，记录字段映射、单位换算、时区和时间基准。区分设定值/实测值、绝压/表压、炉温/片温、工步时长/整批周期；未确认单位的数据不能直接横向排名。
- 将重复记录、计数器复位、跨日批次、缺测、补录、采样间隔与状态重叠的处理写入分析口径。未知不等于零；以数量、时长或产出加权前明确其分母。
- 对比温度、压力、流量与质量时，先按路线、工序、配方版本和可比产品分组。原文范围可帮助提出检查方向，不能自动作为剔除规则、报警上下限或异常标签。
- IV 指标需核实 STC/实测条件、面积定义及百分数/比例表达；EL、PL 的缺陷描述只有在获得相应质量判定规则后才能转成良品率。
- OEE 只有在现场批准了状态映射、计划时间、理想节拍/产能、质量计数与设备层级后才可给出正式结果。资料不足时完成数据概况、事件时间线或带明确假设的演示；不要用缺失值填出一个 OEE。

## 交付与复核

按 [分析报告模板](../../source/templates/analysis-report.md) 记录输入范围、口径、数据问题、结果、证据与待确认项，可按用户要求精简。区分观察到的相关性、工艺解释假设和已验证原因。

对最终结果做与任务相称的校验：关联前后行数与计数守恒、单位维度、时间窗口覆盖、分母为零、重复或复位的影响。保留可重跑的查询或脚本及实际参数。已有表格处理技能可用于格式与公式，但业务口径以本任务证据为准。

引用 `source/references/kd/` 的具体文件与章节；最新行业数据另行核实。不要因知识缺口停止全部工作，只将依赖缺失口径的指标标为待确认。
